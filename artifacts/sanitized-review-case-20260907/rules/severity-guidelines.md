# 严重级别判定指南

## 严重级别（强制）

| 级别 | 判定标准 |
|------|---------|
| `fatal` | 已证实的阻塞问题：安全泄露、数据破坏、确定性崩溃、构建失败，必须阻塞合入 |
| `major` | 已证实会导致行为不正确或关键工作流失败的缺陷，影响未达到 fatal |
| `minor` | 已证实的当前低影响缺陷，或有明确修复价值且不应阻塞合入的显式规则违规 |
| `suggestion` | 风格、优化、可读性、命名偏好、上下文不足的推测、兼容性猜测、扩展性担忧 |

## 决策规则

1. 先判断证据确定性，再判断影响范围。证据较弱时降低级别；无法证明则不报告。
2. `fatal`、`major`、`minor` 必须有来自 diff、完整文件上下文或已加载规则的可验证证据。
3. 潜在未来风险、兼容性猜测、扩展性担忧、假设性调用方/输入/枚举值，必须丢弃。
4. `minor` 不是不确定问题的容器——必须是已证实的当前低影响缺陷或显式规则违规。
5. 不得把 nitpick、提问或潜在未来风险提升为 `fatal`/`major`/`minor`。
6. 风格、可读性、命名、格式类 finding 最高级别是 `suggestion`。

## 内部 severity 映射

| 风险等级 | 内部 severity | 描述 |
|---------|-----------------|------|
| CRITICAL/HIGH | `error` | 严重Bug、安全问题、破坏性变更 |
| MEDIUM | `minor` | 中等优先级、性能问题 |
| LOW | `suggestion` | 轻微问题、代码风格、优化建议 |

## 置信度评分 (confidence_score)

| 分数 | 含义 |
|------|------|
| 9-10 | 铁证：diff行直接证明缺陷，规则明确匹配 |
| 7-8 | 强证：diff+上下文可证明，规则适用 |
| 5-6 | 中等：证据存在但有少量不确定性 |
| 3-4 | 弱证：依赖推测或假设 |
| 0-2 | 极弱：几乎无证据支撑 |

默认最低可报告置信度：**7**（可通过 config.json 调整）
