## 通用规则

### STRUCT-FILE-001: 结构化配置文件跳过魔术数字检视

- **检查锚点**: `.yaml`/`.yml`/`.json`/`.csv`/`.xml`/`.html` 文件中的数值字面量
- **触发条件**: finding 建议将配置文件中的具体数值定义为常量时，必须丢弃该 finding
- **严重程度**: N/A（该类 finding 直接丢弃，不输出）
- **反例**（不应输出的 finding）:
  - `size: ",300"` → 建议"定义为常量 SIZE_WIDTH"
  - `width: 100` → 建议"使用常量替代魔术数字"
  - `color: "#FF0000"` → 建议"提取颜色常量"
  - `timeout: 5000` → 建议"定义为 TIMEOUT_MS"
- **正例**（应关注的真实问题）:
  - `timeout: -1` → 负值不合理（行为缺陷，非魔术数字问题）
  - `replicas: 0` → 零副本导致服务不可用（行为缺陷）

## YAML 文件校验

### YAML-FILE-001: 缩进一致性

- **检查锚点**: `.yaml`/`.yml` 文件 diff 中缩进层级变化
- **触发条件**: 同一文件内缩进风格不一致（混合空格与Tab，或同级元素缩进宽度不同），导致 YAML 解析器层级理解错误
- **严重程度**: fatal（YAML 解析失败或层级错误导致运行时行为不可预测）
- **反例**:
  - 同一层级的两个 key，一个缩进 2 空格，另一个缩进 4 空格 → 解析器认为后者是前者的子键
  - 混合使用 Tab 和空格缩进 → 不同解析器行为不一致
- **正例**:
  - 整个文件统一使用 2 空格缩进
  - 整个文件统一使用 4 空格缩进

### YAML-FILE-002: 键值对格式正确

- **检查锚点**: `.yaml`/`.yml` 文件 diff 中新增或修改的键值对
- **触发条件**: key 后缺少冒号、冒号后缺少空格（`key:value` 而非 `key: value`），或键名重复
- **严重程度**: fatal（YAML 解析报错或静默覆盖前值）
- **反例**:
  - `key value` — 缺少冒号，解析为字符串而非键值对
  - `key:value` — 冒号后无空格，部分解析器不识别为键值对
  - 同一文件中两个 `name: xxx` → 后者覆盖前者，无报错
- **正例**:
  - `key: value` — 标准键值对格式
  - `key:` — 空值（合法）
  - 同级无重复键名

### YAML-FILE-003: 列表格式正确

- **检查锚点**: `.yaml`/`.yml` 文件 diff 中的列表项
- **触发条件**: 列表项前缺少短横线 `-`，或短横线后缺少空格
- **严重程度**: fatal（列表解析失败）
- **反例**:
  - `item1` — 列表项缺少 `-` 前缀，被解析为普通字符串
  - `-item1` — 短横线后无空格，被解析为字符串 "-item1"
- **正例**:
  - `- item1` — 标准列表项
  - `- key: value` — 列表中的映射项

### YAML-FILE-004: 多行字符串引号正确

- **检查锚点**: `.yaml`/`.yml` 文件 diff 中包含 `|`、`>`、`|-`、`>|` 等多行指示符或含特殊字符的字符串
- **触发条件**: 多行字符串使用了不正确的引号包裹，或含 `: `、`# `、`- ` 等特殊字符的值未加引号导致解析歧义
- **严重程度**: major（解析歧义可能导致配置值与预期不符）
- **反例**:
  - `description: This: is a problem` — 值含 `: ` 被解析为新键值对
  - `comment: # not a comment` — `#` 后内容被解析为注释
  - `value: |-` 后缺少正确缩进的文本块
- **正例**:
  - `description: "This: is fine"` — 引号包裹消除歧义
  - `comment: "# not a comment"` — 引号包裹保留 `#` 字符
  - 多行使用 `|` 或 `>` 指示符，后跟正确缩进的文本块

## JSON 文件校验

### JSON-FILE-001: 括号匹配

- **检查锚点**: `.json` 文件 diff 中的 `{}` 和 `[]`
- **触发条件**: 花括号或方括号数量不匹配（多开少闭、少开多闭）
- **严重程度**: fatal（JSON 解析必然失败）
- **反例**:
  - `{"key": "value"` — 缺少闭合 `}`
  - `{"key": ["a", "b"]}` — 正确，但若删除了 `]` 则为 `{"key": ["a", "b"}` → 不匹配
  - 嵌套对象 `{"a": {"b": 1}` — 内层缺少 `}`
- **正例**:
  - `{"key": "value"}` — 花括号成对
  - `{"key": ["a", "b"]}` — 方括号成对
  - 嵌套 `{"a": {"b": 1}}` — 每层括号成对

### JSON-FILE-002: 键名使用双引号

- **检查锚点**: `.json` 文件 diff 中的键名
- **触发条件**: 键名使用单引号或无引号（JSON 规范要求键名必须用双引号）
- **严重程度**: fatal（标准 JSON 解析器拒绝解析）
- **反例**:
  - `{'key': 'value'}` — 单引号键名，JSON 规范不允许
  - `{key: "value"}` — 无引号键名，JSON 规范不允许
- **正例**:
  - `{"key": "value"}` — 双引号键名

### JSON-FILE-003: 末尾无多余逗号

- **检查锚点**: `.json` 文件 diff 中数组或对象的最后一个元素/属性
- **触发条件**: 数组最后一个元素后或对象最后一个属性后有多余逗号
- **严重程度**: fatal（标准 JSON 解析器拒绝解析；部分宽松解析器可接受但不符合规范）
- **反例**:
  - `{"key1": "v1", "key2": "v2",}` — 最后一个属性后多余逗号
  - `[1, 2, 3,]` — 数组末尾多余逗号
- **正例**:
  - `{"key1": "v1", "key2": "v2"}` — 无末尾逗号
  - `[1, 2, 3]` — 无末尾逗号

### JSON-FILE-004: 值类型正确

- **检查锚点**: `.json` 文件 diff 中的值
- **触发条件**: 值不符合 JSON 规范类型（字符串/数字/布尔/null/对象/数组），如未加引号的非数字非布尔非 null 值
- **严重程度**: fatal（JSON 解析失败或值被误解析）
- **反例**:
  - `{"key": undefined}` — `undefined` 不是 JSON 合法值
  - `{"key": 0x1A}` — 十六进制数字，JSON 不支持
  - `{"key": 01}` — 前导零数字，JSON 不支持
- **正例**:
  - `{"key": null}` — null 合法
  - `{"key": true}` — 布尔值合法
  - `{"key": 42}` — 十进制数字合法
  - `{"key": "undefined"}` — 字符串包裹后合法

## CSV 文件校验

### CSV-FILE-001: 列数一致

- **检查锚点**: `.csv` 文件 diff 中新增或修改的行
- **触发条件**: 某行的字段数与标题行（第一行）或其他行不一致
- **严重程度**: major（解析错位导致数据字段对应错误）
- **反例**:
  - 标题行 `id,name,age`（3列），数据行 `1,Alice,30,extra`（4列）→ 第四列无对应标题
  - 标题行 `id,name,age`（3列），数据行 `2,Bob`（2列）→ age 字段缺失
- **正例**:
  - 所有数据行列数与标题行一致

### CSV-FILE-002: 引号正确成对

- **检查锚点**: `.csv` 文件 diff 中含引号的字段
- **触发条件**: 字段内的双引号未正确转义（应为 `""`），或包含逗号的字段未用引号包裹，或引号未成对闭合
- **严重程度**: major（字段被错误拆分或合并）
- **反例**:
  - `value1,"value2,with,comma,value3` — 引号未闭合，后续行全部错位
  - `value1,"He said "hello"",value3` — 内嵌引号未转义为 `""`
  - `value1,value2,with,comma,value3` — 含逗号未用引号包裹，被拆分为4个字段
- **正例**:
  - `value1,"value2,with,comma",value3` — 含逗号字段用引号包裹
  - `value1,"He said ""hello""",value3` — 内嵌引号用 `""` 转义

### CSV-FILE-003: 换行符一致

- **检查锚点**: `.csv` 文件 diff 中新增行
- **触发条件**: 同一文件内混用 CRLF（`\r\n`）和 LF（`\n`）换行符
- **严重程度**: minor（部分工具解析异常，但多数现代工具可处理）
- **反例**:
  - 文件前半部分使用 CRLF，新增行使用 LF → diff 工具可能显示全文变更
  - 同一文件中 `line1\r\nline2\nline3` → 混合换行符
- **正例**:
  - 整个文件统一使用 LF 换行
  - 整个文件统一使用 CRLF 换行

## HTML 文件校验

### HTML-FILE-001: 标签正确闭合

- **检查锚点**: `.html`/`.htm` 文件 diff 中新增或修改的标签
- **触发条件**: 非自闭合标签缺少对应的闭合标签，或自闭合标签格式错误
- **严重程度**: major（页面渲染异常或脚本/样式加载失败）
- **反例**:
  - `<div>content` — 缺少 `</div>` 闭合
  - `<br>` 在 XHTML 中应为 `<br/>`
  - `<script src="app.js">` — 缺少 `</script>` 闭合
- **正例**:
  - `<div>content</div>` — 成对闭合
  - `<br/>` 或 `<br>`（HTML5 允许） — 自闭合标签
  - `<script src="app.js"></script>` — script 标签必须有闭合

### HTML-FILE-002: 标签嵌套正确

- **检查锚点**: `.html`/`.htm` 文件 diff 中新增的嵌套标签结构
- **触发条件**: 块级元素与内联元素嵌套违反 HTML 规范（如内联元素包含块级元素），或标签交叉闭合
- **严重程度**: major（浏览器容错渲染但行为不可预测，不同浏览器表现不一致）
- **反例**:
  - `<span><div>block inside inline</div></span>` — 内联元素包含块级元素
  - `<a><div>link block</div></a>` — a 标签包含块级元素（HTML5 部分允许，但旧浏览器不支持）
  - `<b><i>text</b></i>` — 标签交叉闭合
- **正例**:
  - `<div><span>inline inside block</span></div>` — 块级包含内联
  - `<b><i>text</i></b>` — 正确嵌套闭合

### HTML-FILE-003: 属性值使用引号

- **检查锚点**: `.html`/`.htm` 文件 diff 中的标签属性
- **触发条件**: 属性值未用引号包裹，或含空格/特殊字符的属性值缺少引号
- **严重程度**: minor（多数浏览器容错，但属性值含空格时解析错误）
- **反例**:
  - `<input type=text>` — 属性值无引号
  - `<div class=main content>` — 含空格的属性值无引号，被解析为 `class="main"` + 布尔属性 `content`
  - `<a href=https://example.com/path?q=1&r=2>` — 含 `&` 的 URL 无引号
- **正例**:
  - `<input type="text">` — 双引号包裹
  - `<div class="main content">` — 含空格属性值用引号包裹
  - `<a href="https://example.com/path?q=1&r=2">` — URL 用引号包裹
